volatile 关键字详解

发表于2026-06-02|更新于2026-06-02
|阅读量:

volatile 是 Java 提供的轻量级同步机制，常用于 状态标志、双重检查单例、一写多读 等场景。它不能保证复合操作的原子性，但能解决 可见性 与部分 有序性 问题。

1. 解决了什么问题？

多线程下，每个线程可能将变量副本放在 工作内存（CPU 缓存） 中，主内存的修改对其它线程未必立即可见。volatile 修饰的变量读写会直接与主内存交互（语义上禁止某些缓存优化），从而保证：

  1. 可见性：一个线程写入后，其它线程能尽快看到新值。
  2. 禁止指令重排序（在 JVM 内存屏障语义下）：避免特定场景下的乱序执行带来逻辑错误。

不保证：i++ 这类读-改-写复合操作的原子性，仍需 synchronized 或原子类。

2. 内存语义（简化理解）

对 volatile 变量的写，会在写之后插入 StoreStore + StoreLoad 屏障；对 volatile 变量的读，会在读之前插入 LoadLoad + LoadStore 屏障。效果是：

  • 写 volatile 之前的操作，不会排到写之后；
  • 读 volatile 之后的操作，不会排到读之前。

因此常把 volatile 作为 happens-before 的锚点：线程 A 写 volatile 变量 happens-before 线程 B 随后读该变量。

3. 典型用法

3.1 状态标志

若 stopped 不用 volatile，工作线程可能永远看不到 true，导致无法优雅退出。

3.2 双重检查锁定（DCL）单例

new Singleton() 在字节码层面可能重排序为：分配内存 → 设置引用 → 初始化对象。若无 volatile，其它线程可能拿到未完全初始化的实例。volatile 禁止这种重排序。

4. volatile 与 synchronized 对比

维度 volatile synchronized
原子性 仅单读/单写 保证代码块原子性
可见性 是 是
有序性 有限禁止重排 是
阻塞 不阻塞 可能阻塞
适用 一写多读标志位 临界区互斥

5. 常见误区

  1. 用 volatile 实现计数器：count++ 仍非原子，应使用 AtomicInteger 等。
  2. 以为 volatile 能替代锁：多个变量之间的复合不变式仍需锁或原子类保证。
  3. 与 JMM 文章混淆：volatile 是 JMM 中的具体关键字，学习时可结合 happens-before 规则一起理解。

6. 小结

volatile 适合 变量只被单个线程写、被多个线程读 且 写操作不依赖当前值 的场景。需要互斥或复合原子操作时，应选用 synchronized、Lock 或 java.util.concurrent.atomic 包下的类。
