CountDownLatch、CyclicBarrier 与 Semaphore

发表于2026-06-02|更新于2026-06-02
|阅读量:

java.util.concurrent 除了线程池、阻塞队列，还提供多种 协作式同步工具，用于线程间的 等待、汇合与资源限流。本文介绍 CountDownLatch、CyclicBarrier、Semaphore，并与已学过的 ReentrantLock 等区分。

1. CountDownLatch — 倒数关门

作用：一个或多个线程等待 其它线程完成若干次操作 后再继续。计数器只能 减不能增，减到 0 后等待线程被唤醒，不可重置。

典型场景：

  • 主线程等待多个并行任务结束再汇总结果；
  • 模拟高并发压测前，等待所有线程就绪（配合 await / countDown）。

注意：countDown 应在 finally 中调用，避免异常导致永远 await 阻塞。

2. CyclicBarrier — 循环栅栏

作用：一组线程 互相等待，直到到达同一屏障点再一起继续。计数到 0 后会 自动重置，可重复使用（cyclic）。

可选构造：CyclicBarrier(int parties, Runnable barrierAction) 在最后一员到达时执行一次屏障任务（如合并分片结果）。

典型场景：多阶段流水线、分治计算中各子任务阶段同步。

与 CountDownLatch 对比

维度 CountDownLatch CyclicBarrier
等待方 一个（或多个）线程等其它完成 所有参与线程互相等
重用 否 是
计数方向 countDown 递减 await 到达后重置

3. Semaphore — 信号量

作用：控制 同时访问某资源的线程数量（许可证 permit）。支持公平/非公平策略。

常用 API：

  • acquire() / acquire(n)：获取许可，不足则阻塞；
  • tryAcquire(timeout, unit)：限时获取；
  • release() / release(n)：归还许可。

典型场景：

  • 数据库连接池、对象池并发上限；
  • 接口限流（单机维度）；
  • 停车场空位模型。

注意：release 次数不应超过 acquire，否则会增加多余 permit，破坏限流语义。

4. 三者与锁的区别

  • Lock / synchronized：互斥，同一时刻只有一个线程进入临界区（读写锁除外）。
  • Latch / Barrier：协调 执行顺序与汇合时机，不强调互斥修改同一变量。
  • Semaphore：限制 并发度，多个线程可同时持有多个许可。

6. 小结

  • CountDownLatch：一次性的「等大家都做完」；
  • CyclicBarrier：多轮「到齐再一起走」；
  • Semaphore：「只有 N 个名额」。
