HashMap 源码解析

发表于2026-06-02|更新于2026-06-02
|阅读量:

HashMap 是日常开发中使用频率最高的集合之一。理解它的底层实现，有助于写出更合理的代码，也能为学习 ConcurrentHashMap、LinkedHashMap 打下基础。本文基于 JDK 8 梳理 HashMap 的核心设计。

1. 整体结构

JDK 8 之后，HashMap 由 数组 + 链表 + 红黑树 组成：

  • 底层是 Node<K,V>[] table 数组，每个下标称为一个 桶（bucket）。
  • 哈希冲突时，同一桶内用链表串联；链表长度超过阈值（默认 8）且数组长度 ≥ 64 时，链表转为 红黑树。
  • 树节点退化为链表的条件是树节点数 ≤ 6。

2. 哈希定位

put 时通过 (n - 1) & hash 计算下标，其中 n 为数组长度（必须为 2 的幂）。hash 由高 16 位与低 16 位异或得到，目的是让高位也参与运算，减少碰撞：

为什么容量是 2 的幂？ 取模可优化为位与运算，且扩容时元素下标要么不变，要么变为 oldIndex + oldCapacity，迁移成本更低。

3. put 流程简述

  1. 若 table 为空，先 resize() 初始化。
  2. 计算下标，若桶为空，直接放入新 Node。
  3. 若 key 已存在（hash 相等且 equals），更新 value。
  4. 若为树节点，走 TreeNode.putTreeVal。
  5. 否则在链表尾部追加；追加后若链表长度 ≥ 8，尝试 treeifyBin。
  6. size 自增，超过 threshold（容量 × 负载因子）则扩容。

4. 扩容（resize）

扩容时容量变为原来的 2 倍，threshold 同步翻倍。每个元素重新计算下标：

  • 若 (e.hash & oldCap) == 0，下标不变；
  • 否则下标为 oldIndex + oldCap。

这一技巧避免了重新计算完整哈希，是 JDK 8 的重要优化。

5. get 流程

  1. 计算下标，取桶头节点。
  2. 头节点即目标则返回。
  3. 若为树，在红黑树中查找。
  4. 否则遍历链表，匹配 hash 与 equals。

6. 与 Hashtable、ConcurrentHashMap 对比

特性 HashMap Hashtable ConcurrentHashMap
线程安全 否 是（synchronized 方法） 是
null key/value 允许 不允许 不允许
性能 高 低 高（分段/CAS）

7. 使用注意

  1. **重写 equals 必须重写 hashCode**，否则相同逻辑的对象可能落在不同桶，导致重复 key 或查不到。
  2. 初始容量 预估可避免多次扩容；new HashMap<>(expectedSize) 时，内部会按 loadFactor 反算容量。
  3. 遍历修改 会触发 fail-fast（modCount 变化抛 ConcurrentModificationException），并发场景用 ConcurrentHashMap 或迭代时勿结构性修改。
  4. JDK 7 在并发下扩容可能形成 环形链表（死循环），JDK 8 改为头插改尾插 + 拆分链表，已修复该问题。

8. 小结

HashMap 通过数组下标 O(1) 定位、链表与红黑树处理冲突、按负载因子扩容，在时间与空间之间取得平衡。掌握 哈希计算、put/get、扩容与树化 四条主线，即可应对大部分面试与排障场景。
