JVM 垃圾回收机制入门

发表于2026-06-02|更新于2026-06-02
|阅读量:

Java 通过 自动垃圾回收（GC） 管理堆内存，开发者无需手动 free。理解 GC 有助于解释 OOM、长时间 STW（Stop-The-World）、Metaspace 溢出 等问题。本文面向 JDK 8 常见配置做入门梳理。

1. 哪些内存需要 GC？

区域 线程共享 是否 GC 说明
堆（Heap） 是 是 对象实例主体
方法区 / Metaspace 是 是（类卸载等） 类元信息、常量池等
虚拟机栈、本地方法栈 否 否 栈帧随线程结束释放
程序计数器 否 否 当前指令地址

堆 是 GC 的主战场，又分为 新生代 与 老年代（分代假说：多数对象朝生夕死）。

2. 堆的分代结构

  • 新生代：Eden + 2 个 Survivor（S0、S1），比例常为 8:1:1（-XX:SurvivorRatio=8）。
  • 老年代：长期存活对象、大对象（超过 -XX:PretenureSizeThreshold 可能直接进入老年代）。

Minor GC：清理新生代，频率高、停顿通常较短。
Major GC / Full GC：常涉及老年代，甚至整堆与方法区，停顿更长。

对象分配流程（简化）：先在 Eden 分配 → Minor GC 后存活对象复制到 Survivor → 在 Survivor 间复制并 年龄 +1 → 达到阈值（默认 15）晋升老年代。

3. 如何判断对象可回收？

3.1 引用计数法

实现简单，但无法处理循环引用，Java 未采用。

3.2 可达性分析（主流）

从 GC Roots 出发，不可达的对象可被回收。GC Roots 包括：

  • 虚拟机栈中引用的对象；
  • 方法区静态属性、常量引用的对象；
  • 本地方法栈 JNI 引用的对象；
  • 同步锁持有的对象；
  • JVM 内部常量、类加载器等。

3.3 四种引用

  • 强引用：普通 new，不回收直到不可达。
  • 软引用：内存不足前可回收，适合缓存。
  • 弱引用：下一次 GC 即回收，WeakHashMap 键即此类。
  • 虚引用：用于跟踪回收通知，本身无实际语义。

4. 常见 GC 算法

算法 思路 优点 缺点
标记-清除 标记存活，清除其余 实现简单 碎片
标记-复制 存活对象复制到另一块 无碎片、适合新生代 空间浪费
标记-整理 存活对象向一端移动 适合老年代 移动成本高

新生代多用 复制；老年代多用 标记-清除 或 标记-整理。

5. 常见收集器（JDK 8）

  • Serial / Serial Old：单线程，客户端或小堆。
  • ParNew：新生代多线程，常配合 CMS。
  • Parallel Scavenge + Parallel Old：吞吐量优先，JDK 8 默认组合之一。
  • CMS（Concurrent Mark Sweep）：以最短停顿为目标，已逐步被 G1 取代。
  • G1：将堆划分为 Region，可预测停顿，JDK 9+ 默认，JDK 8 可通过 -XX:+UseG1GC 启用。

6. 调优参数速查

原则：先定位问题（日志、MAT 分析 dump），再调参；盲目增大堆可能掩盖泄漏。

7. OOM 常见类型

  1. Java heap space：对象过多或泄漏。
  2. GC overhead limit exceeded：反复 GC 仍回收不足。
  3. Metaspace：类加载过多、动态代理、热部署。
  4. unable to create new native thread：线程数过多或系统限制。

8. 小结

JVM GC 建立在 分代 + 可达性分析 之上，通过不同收集器在 吞吐量 与 停顿时间 之间权衡。线上问题建议结合 jstat、jmap、heap dump 与 GC 日志分析，再决定是优化代码还是调整堆与收集器。
