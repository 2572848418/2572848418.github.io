死锁原理与排查实战

发表于2026-06-03|更新于2026-06-02
|阅读量:

死锁是多线程互相等待对方持有的锁，导致 永久阻塞。线上表现为接口超时、线程池打满，需结合线程 dump 定位。

1. 四个必要条件（同时满足才可能死锁）

  1. 互斥：资源只能被一个线程占用；
  2. 占有且等待：持有至少一个资源，并等待其它资源；
  3. 不可抢占：资源只能由持有者释放；
  4. 循环等待：存在线程资源的环形链。

破坏任一条件可预防死锁，工程上最常用 固定加锁顺序、超时 tryLock。

3. 预防与避免

手段 说明
统一顺序 所有线程按相同顺序获取多把锁
tryLock lock.tryLock(timeout) 超时放弃并告警
减少锁粒度 缩短持锁时间，避免嵌套锁
无锁结构 队列、CAS 减少互斥
数据库 固定表/行访问顺序，避免交叉更新

4. 排查工具

jstack

搜索 Found one Java-level deadlock，会列出参与死锁的线程与锁。

jconsole / VisualVM

图形化查看线程状态与死锁检测。

日志

线程池 RejectedExecutionException 可能是下游死锁导致任务无法完成，需结合 dump 而非只看表象。

5. 活锁与饥饿

  • 活锁：线程未阻塞，但互相让步重试，仍无法推进（如两人走廊相遇反复让路）；
  • 饥饿：低优先级或非公平锁长期得不到资源。

6. 小结

写代码时 约定全局锁顺序；使用 ReentrantLock 时优先带超时的 tryLock；线上卡住先抓 thread dump 看是否死锁，再分析锁竞争与慢 SQL。
