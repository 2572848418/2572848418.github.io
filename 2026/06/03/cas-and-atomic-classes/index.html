CAS 与原子类详解

发表于2026-06-03|更新于2026-06-02
|阅读量:

CAS（Compare And Swap） 是无锁编程的基础，JDK 的 java.util.concurrent.atomic 包与 AQS 都建立在 CAS 之上。

1. CAS 是什么？

语义：仅当内存位置的值等于 期望值 时，才更新为 新值，否则重试或失败。CPU 提供原子指令（如 x86 的 CMPXCHG），JDK 通过 Unsafe 或 VarHandle 封装。

2. AtomicInteger 示例

3. 原子类家族

类 用途
AtomicInteger / Long 计数器
AtomicReference 引用 CAS
AtomicStampedReference 带版本号，缓解 ABA
LongAdder / LongAccumulator 高并发累加，分段减少竞争
AtomicIntegerArray 数组元素原子更新

4. ABA 问题

线程 A 读到值 A → 线程 B 改为 B 再改回 A → A 的 CAS 仍成功，但中间状态已变。
解决：AtomicStampedReference 比较值 + 版本戳。

5. CAS 与锁的关系

  • 优点：无阻塞，避免上下文切换，低竞争时快。
  • 缺点：高竞争下自旋浪费 CPU；只能保证 单个变量 原子，复合逻辑需 synchronized 或锁。

ReentrantLock、Semaphore 底层 AQS 用 CAS 修改 state 队列节点。

6. LongAdder 为何更快？

将值分散到多个 Cell，不同线程更新不同 Cell，最后 sum() 汇总，类似分段锁思想，空间换时间，适合统计计数、Metrics。

7. 小结

CAS 实现乐观锁与无锁数据结构；业务计数优先 LongAdder；需要多变量一致性时用锁或事务，不要强行拼多个 CAS。
