String 不可变性与字符串常量池

发表于2026-06-03|更新于2026-06-02
|阅读量:

String 是 Java 使用最多的类型之一。理解其 不可变性 与 常量池，有助于解释内存行为、线程安全以及 == 与 equals 的差异。

1. 为什么 String 不可变？

String 内部用 final char[]（JDK 9+ 为 byte[] + 编码标志）保存字符，且类被 final 修饰，无提供修改内容的方法。好处包括：

  • 线程安全：多线程共享同一字符串无需同步；
  • 哈希缓存：hash 可缓存，适合作为 HashMap 的 key；
  • 常量池复用：内容不变才能安全共享；
  • 安全：网络连接、文件路径等参数不被篡改。

3. intern() 与 JDK 7+ 变化

  • JDK 6：常量池在永久代（PermGen），intern 易撑满永久代。
  • JDK 7+：字符串常量池移到 堆，intern 可在 OOM 前被 GC，仍要注意大量 intern 导致堆压力。

适用：重复极高、确定生命周期的字符串（如配置 key），不宜滥用。

5. 与 HashMap 的配合

作为 key 时依赖 不可变 + 正确 hashCode/equals。若 key 内容可变，放入 Map 后修改会导致「找不到」。

6. 小结

比较内容用 equals；比较引用用 == 仅在你明确需要判断是否为同一对象时。大量动态字符串用 StringBuilder；可复用字面量让 JVM 自动入池，慎用手动 intern。
