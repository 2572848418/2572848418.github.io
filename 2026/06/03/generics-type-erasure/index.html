Java 泛型与类型擦除

发表于2026-06-03|更新于2026-06-02
|阅读量:

泛型（Generics）在 JDK 5 引入，提供编译期类型检查，减少强制转型。Java 采用 类型擦除 实现，理解擦除有助于解释诸多「看起来不合理」的编译错误。

2. 类型擦除是什么？

编译后泛型信息在字节码中 大部分被擦除，List<String> 与 List<Integer> 在运行时都是 原始类型 List（配合类型转换与桥接方法）。

3. 通配符与 PECS

  • <? extends T>：上界，只读为主（Producer extends）— 不能安全 add（除 null）。
  • <? super T>：下界，可写入 T 及其子类（Consumer super）— 读取只能用 Object。

PECS：Producer Extends, Consumer Super。

4. 常见编译问题

数组与泛型不兼容：new List<String>[10] 非法，因为数组协变会导致堆污染。

5. 类型擦除的应对

需求 手段
需要 Class 构造函数传入 Class<T>
创建 T 实例 工厂、Supplier<T>
保留泛型信息（反射） ParameterizedType、TypeReference（Jackson）
运行时判断泛型 子类化父类带泛型，如 new TypeToken<List<String>>(){}（Guava/Gson）

6. 小结

泛型提升 编译期安全，擦除保证与旧字节码兼容。写 API 时善用通配符与 PECS；需要运行时类型信息时，显式传递 Type 或使用类型令牌模式。
