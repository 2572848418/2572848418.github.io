Java 反射机制详解

发表于2026-06-03|更新于2026-06-02
|阅读量:

反射（Reflection）允许程序在运行时检查、修改自身行为，例如获取类的字段、方法并动态调用。Spring、MyBatis、JUnit 等框架大量依赖反射。

2. 常用 API

3. 性能与 setAccessible

  • 反射调用比直接调用慢，JVM 可通过 方法句柄（MethodHandle）、缓存 Method 对象缓解。
  • JDK 9+ 模块系统下，非法访问会警告；需 --add-opens 或合理使用 setAccessible。

4. 典型应用场景

场景 说明
依赖注入 Spring 根据类型/注解创建 Bean
ORM 映射 MyBatis 将 ResultSet 映射到实体字段
动态代理 JDK 动态代理基于接口方法反射
注解处理 运行时读取 @RequestMapping 等
序列化 部分 JSON 库通过反射读写字段

5. 与注解、动态代理的关系

  • 注解：编译期或运行期的元数据，常配合反射读取。
  • 动态代理：Proxy.newProxyInstance 在运行时生成接口实现，内部通过反射调用真实对象方法。

6. 使用注意

  1. 破坏封装：可访问 private 成员，生产代码应谨慎。
  2. 类型安全：编译期无法检查，错误推迟到运行时。
  3. ProGuard/R8：Android 混淆需保留反射用到的类名与方法名。

7. 小结

反射是 Java 元编程 的基础能力，框架层不可或缺，业务层应优先接口、工厂、注解处理器等更清晰的方式；必须用反射时，注意性能与模块访问限制。
