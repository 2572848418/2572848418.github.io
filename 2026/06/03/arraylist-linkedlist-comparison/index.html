ArrayList 与 LinkedList 对比与选型

发表于2026-06-03|更新于2026-06-02
|阅读量:

List 接口最常用的两个实现是 ArrayList 和 LinkedList。面试常问差异，实际开发中更重要的是 按访问模式选型。

1. 底层结构

实现 底层 内存特点
ArrayList 动态数组 Object[] 连续内存，缓存友好
LinkedList 双向链表 Node 每个元素额外存 prev/next 指针

2. 时间复杂度对比

操作 ArrayList LinkedList
随机访问 get(i) O(1) O(n)
头尾插入 add 尾 O(1)*，头 O(n) O(1)
中间插入 add(i,e) O(n) 移动元素 O(n) 查找 + O(1) 链接
删除 O(n) 移动 O(n) 查找 + O(1) 断开
按值查找 O(n) O(n)

* 均摊 O(1)，扩容瞬间 O(n)。

3. 常见误区

误区 1：「插入删除 LinkedList 一定更快。」
中间插入时，ArrayList 要移动后续元素，LinkedList 要先 遍历到第 i 个节点，两者都是 O(n)，常数因子下 ArrayList 未必更慢。

误区 2：「LinkedList 省内存。」
每个节点除元素外还有前后指针，对象头开销大，元素少时往往比 ArrayList 更占内存。

4. 选型建议

  • 默认用 ArrayList：读多、遍历多、按索引访问、尾部追加。
  • Deque 场景：需要队列/双端队列时，优先 ArrayDeque（数组实现，通常比 LinkedList 更快），而非 LinkedList。
  • 频繁在已知节点引用旁插入：可考虑 LinkedList（实际业务极少）。

5. 线程安全

二者均非线程安全。并发场景使用：

  • Collections.synchronizedList(list)
  • CopyOnWriteArrayList（读多写少）
  • 或外层用锁 / 并发容器

6. 小结

没有「绝对更好」的 List，只有是否匹配访问模式。绝大多数业务列表用 ArrayList 即可；LinkedList 在 JDK 源码注释里也常被 ArrayDeque 替代用于栈和队列。
